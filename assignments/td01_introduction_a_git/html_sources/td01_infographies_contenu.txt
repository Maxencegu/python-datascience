INFOGRAPHIE 01 — Maîtriser ses Analyses : Guide de la Gestion de Versions pour l'Économiste
================================================================

La gestion de versions est essentielle pour organiser, suivre et sécuriser vos projets de données, garantissant reproductibilité et collaboration.

--- SECTION : Les Fondamentaux de la Gestion de Versions ---

Qu'est-ce que la gestion de versions ?
Un ensemble de processus permettant de gérer les modifications de fichiers, de programmes et de dossiers au fil du temps.

Un suivi indispensable pour le code et les données
Cruciale pour tout élément qui évolue ou qui doit être partagé, garantissant que chaque étape de l'analyse est documentée.

La "recette" de votre projet
Sans gestion de versions, reproduire les résultats d'une analyse complexe est aussi difficile que de refaire un plat sans recette précise.

--- SECTION : Pourquoi l'adopter pour vos projets ? ---

Le filet de sécurité : le "Rollback"
Si une nouvelle modification corrompt votre script ou vos résultats, vous pouvez instantanément revenir à une version antérieure fonctionnelle.

Une traçabilité complète
Git permet de comparer les fichiers à différents stades, d'identifier l'auteur des modifications et de comprendre le "pourquoi" de chaque changement.

Travail collaboratif sans conflit
Plusieurs chercheurs peuvent travailler séparément sur différentes parties d'un projet avant de fusionner leurs versions en toute sécurité.

--- SECTION : Débuter avec Git et le Terminal ---

Le Shell (ou Terminal)
L'interface textuelle utilisée pour exécuter les commandes Git et naviguer dans l'arborescence de votre ordinateur.

Naviguer dans vos répertoires
Utilisez des commandes simples pour savoir où vous êtes et lister vos fichiers avant de commencer à versionner votre travail.

Git est open source et évolutif
Logiciel gratuit et universel, il s'adapte aussi bien à un petit projet de mémoire qu'à des analyses de données massives en équipe.

--- AIDE-MÉMOIRE DES COMMANDES DE BASE ---

pwd
Affiche le chemin du dossier dans lequel vous vous trouvez actuellement.

ls
Liste tous les fichiers et sous-dossiers présents dans votre répertoire actuel.

cd
Permet de se déplacer vers un autre dossier (ex : accéder au dossier "Analyses_Economiques").

git --version
La première commande à tester pour vérifier que Git est correctement installé sur votre système.

INFOGRAPHIE 02 — Git pour les Économistes : Maîtriser la Gestion de vos Projets de Recherche
================================================================

--- SECTION : Anatomie d'un dépôt Git ---

Un dépôt = Fichiers de travail + Historique Git. Git crée un dossier caché .git qui stocke tout l'historique de votre projet.

Exemple de projet de recherche :
  Fichiers : données.csv  analyse.R  rapport.md
  + dossier caché : .git

RÈGLE IMPORTANTE : Ne modifiez jamais le dossier .git. Sa suppression ou modification manuelle corromprait l'historique de votre projet.

--- SECTION : Pourquoi adopter Git en Économie ? ---

Suivi systématique des versions
Comparez facilement les résultats d'un modèle économétrique entre deux dates ou revenez à une version antérieure de votre code.

Collaboration simplifiée
En hébergeant votre dépôt sur le cloud, travaillez simultanément avec vos co-auteurs sans risque de doublons ou d'écrasement de fichiers.

--- GUIDE DE MISE EN PLACE ---

OPTION 1 — NOUVEAU PROJET
  git init nom-du-projet
  Crée instantanément un nouveau dossier structuré avec un suivi de versions actif.

OPTION 2 — PROJET EXISTANT
  git init
  Placez-vous dans le dossier de votre recherche actuelle et tapez git init pour commencer le suivi des fichiers déjà présents.

VÉRIFICATION DU STATUT
  git status
  Permet de confirmer que le dépôt est actif et d'identifier les fichiers qui ne sont pas encore suivis.

ERREUR À ÉVITER — Dépôts imbriqués
Sauf cas complexe, ne créez pas un dépôt Git à l'intérieur d'un autre. Cela crée des conflits de suivi de versions entre les deux répertoires .git.

INFOGRAPHIE 03 — Maîtriser son Flux de Travail Git : De la Modification à la Sauvegarde Finale
================================================================

--- ÉTAPE 1 : Modification des fichiers ---
Travaillez normalement sur votre ordinateur.

Modifiez vos scripts d'analyse ou vos documents comme vous le feriez habituellement dans votre répertoire de travail.
Git observe les changements en arrière-plan sans interrompre votre travail. Vous décidez quand et ce que vous souhaitez enregistrer.

--- ÉTAPE 2 : Zone de Staging (Préparation) ---
Marquez les fichiers prêts à être sauvegardés.

La zone de staging permet de sélectionner précisément ce que vous souhaitez inclure dans votre prochaine sauvegarde.

  git add [nom_du_fichier]
  Ajouter un fichier spécifique (ex : script_analyse.R).

  git add .
  Ajouter tout le contenu du répertoire actuel.

--- ÉTAPE 3 : Le Commit (Validation) ---
Enregistrez un instantané permanent.

Le commit capture l'état exact de vos fichiers à un instant T, créant un point de restauration sécurisé.

  git commit -m "Message"
  Valider avec un message explicatif (ex : "Correction du modèle de régression").

--- L'analogie de la lettre : Staging vs Commit ---

STAGING (OUVERT) — L'enveloppe
Vous pouvez ajouter ou retirer des documents tant que l'enveloppe est ouverte.

COMMIT (POSTÉ) — La boîte aux lettres
Une fois postée dans la boîte, l'envoi est définitif et enregistré.

--- L'instantané (Snapshot) ---

Une photo de votre projet à un moment précis.
Chaque commit génère un identifiant unique (hash) qui permet de comparer les versions ou de revenir en arrière si vos résultats économiques divergent.
Exemples de hashs : ab12f4e · 7f3a2d9 · c5e1b08

INFOGRAPHIE 04 — La Science des Commits Git : Maîtrisez l'Historique de vos Données
================================================================

--- L'ANATOMIE D'UN COMMIT ---

Commit (Métadonnées) :
  Auteur   : [Nom]
  Date     : [JJ/MM/AAAA]
  Heure    : [HH:MM]
  Message  : [Description]

L'Arborescence (Tree) — Dictionnaire répertoriant noms et emplacements des fichiers au moment du commit.
Le Blob (Binary Large Object) — Instantané compressé du contenu d'un fichier (ex : .R, .csv).

--- SCÉNARIO — COMMIT 1 : ÉTAT INITIAL ---

Enregistrement initial des fichiers. Git crée des blobs pour chacun.
  report.md                   [nouveau]
  mental-health-survey.csv    [nouveau]
Git crée un blob pour chaque fichier afin de capturer leur contenu.

--- SCÉNARIO — COMMIT 2 : AJOUT DE L'ANALYSE ---

Ajout d'un nouveau fichier summary-statistics.csv.
  report.md                   (pointe vers blob commit 1)
  summary-statistics.csv      [nouveau]
Comme report.md n'a pas changé, l'arborescence pointe vers le blob existant pour économiser de l'espace.

--- SCÉNARIO — COMMIT 3 : MISE À JOUR DES DONNÉES ---

Modification des données CSV. Git crée un nouveau blob mis à jour.
  report.md                   (inchangé)
  mental-health-survey.csv    (v2) [mis à jour]
Les fichiers inchangés continuent de pointer vers leurs anciennes versions.

--- LA SIGNATURE NUMÉRIQUE (LE HACHAGE) ---

Le Hash — empreinte de 40 caractères. Git génère un identifiant unique basé sur le contenu du fichier.

  Fichier A              → 7a2f4c9...
  Fichier B (identique)  → 7a2f4c9...

Même contenu = même hash. Git compare les hashs pour synchroniser les données rapidement.
Intégrité — Si deux fichiers sont identiques, leurs hashs le sont aussi.

--- NAVIGUER DANS LE TEMPS ---

  $ git log

  commit c39d4...  (HEAD)
  Auteur : [Nom]  Date : [Date]
  Message: Modification des données CSV

  commit b20e3...
  Auteur : [Nom]  Date : [Date]
  Message: Ajout summary-statistics.csv

  commit o17f2...
  Message: Enregistrement initial

  Barre d'espace pour défiler · touche q pour quitter

INFOGRAPHIE 05 — Maîtriser l'Historique Git : Du Chaos au Contrôle pour les Économistes
================================================================

--- ÉTAPE 1 : Dompter le flux d'informations ---

Limiter le nombre de commits
  git log -3
  N'affiche que les 3 derniers commits pour éviter d'être submergé par l'historique complet.

Cibler un fichier spécifique
  git log [nom_du_fichier]
  Pour voir l'évolution de vos données. Masque les changements non pertinents des autres documents.

Combiner pour plus de précision
  git log -2 donnees.csv
  Isole instantanément les deux dernières modifications apportées à votre jeu de données.

--- ÉTAPE 2 : Voyager dans le temps avec précision ---

Filtrer par dates avec --since et --until
  git log --since="2024-01-15"
  Affiche les commits effectués entre deux moments précis, pour isoler le travail d'une semaine de collecte de données.

Adopter le format standard ISO 8601
  AAAA-MM-JJ
  ex : 2024-07-15 — format universel, sans ambiguïté

La flexibilité du langage naturel
  --since="2 weeks ago"
  Git comprend aussi des expressions simples comme "yesterday" ou "last month".

--- ÉTAPE 3 : Inspecter et Diagnostiquer ---

Identifier le Hash unique
Repérez l'identifiant unique du commit suspect dans le log ; les 8 à 10 premiers caractères suffisent généralement.
  git log --oneline

Révéler les changements avec git show
  git show [hash]
  Permet de voir exactement quelles lignes ont été ajoutées ou supprimées dans ce commit spécifique.

Exemple de sortie git show :
  @@ -1,3 +1,3 @@
  Sexe,Revenu
  -Homme,50000
  +50000,Homme

Détecter une erreur de structure
L'inspection peut révéler qu'une colonne "Sexe" a été inversée avec "Revenu", expliquant une anomalie dans vos résultats économiques.

INFOGRAPHIE 06 — Maîtriser git diff : Suivre l'évolution de vos analyses économiques
================================================================

Comparez précisément ce qui a changé — dans vos fichiers, votre zone de staging et votre historique.

--- Qu'est-ce qu'un diff ? ---

La méthode de Git pour afficher les différences exactes entre deux versions d'un même fichier.

Exemple :
  report.md — V1 :  # Rapport / Taux : 2 % / Conclusion.
  report.md — V2 :  # Rapport / Taux : 2,5 % / Conclusion.

Git repère chaque ligne modifiée, ajoutée ou supprimée.

--- 1. Comparer le travail en cours ---

  git diff report.md
  Compare la dernière version validée avec les modifications en cours — celles non encore ajoutées au staging.

Exemple de sortie :
  @@ -3,4 +3,4 @@ # Rapport 2023
  Analyse de l'inflation.
  -Taux directeur : 2 %
  +Taux directeur : 2,5 %
  Impact notable.

--- 2. Décoder les résultats ---

  - (rouge) Ligne supprimée — présente dans l'ancienne version, absente de la nouvelle.
  + (vert)  Ligne ajoutée — absente de l'ancienne version, présente dans la nouvelle.

Lecture de @@ -3,4 +3,4 @@ :
  -3,4 : Ancienne version, ligne 3, 4 lignes de contexte
  +3,4 : Nouvelle version, ligne 3, 4 lignes de contexte

--- 3. Comparer après avoir stagé ---

  git diff --staged
  Compare la zone de staging avec la dernière validation — ce qui sera inclus dans le prochain commit.

Exemple de sortie :
  --- a/data/survey.csv
  +++ b/data/survey.csv
  id,age,score
  1,24,7
  +2,31,4
  +3,28,8

Sans nom de fichier, compare tous les fichiers stagés d'un coup.

--- 4. Comparer deux commits ---

  git diff [hash_1] [hash_2]
  Utilisez git log pour trouver les hashs, puis comparez deux points précis de l'historique.

  $ git log --oneline
  a3f8c1e Correction données
  b72e9d4 Import initial

  $ git diff b72e9d4 a3f8c1e

Raccourci HEAD — HEAD désigne votre dernier commit.
Comparer les deux derniers : git diff HEAD~1 HEAD

--- VUE D'ENSEMBLE : LES TROIS ZONES GIT ---

  Répertoire de travail (WD)  --[git diff]-->  Zone de staging (ST)  --[git diff --staged]-->  Dépôt Git (RP)
  Modifications en cours                        Prêt pour le commit                               Historique validé

Pour comparer deux commits : git diff [hash_1] [hash_2]  ·  git diff HEAD~1 HEAD

INFOGRAPHIE 07 — Restaurer et Annuler les Modifications Git
================================================================

Trois commandes pour corriger les erreurs selon leur stade : commit validé, fichier unique ou fichier en staging.

SCÉNARIO TYPE :
Vous avez modifié report.md, effectué un commit — puis réalisé qu'il contient une faute de frappe. La commande à utiliser dépend du stade de votre travail.

--- COMMIT VALIDÉ — TOUS LES FICHIERS : git revert ---

Crée un nouveau commit qui rétablit tous les fichiers dans l'état du commit ciblé. L'historique est préservé.

Annuler le dernier commit :
  git revert HEAD

Annuler l'avant-dernier commit :
  git revert HEAD~1

Un hash de commit est accepté à la place de HEAD. Ouvre par défaut un éditeur pour le message de commit.
ATTENTION : annule tous les fichiers du commit ciblé, pas seulement un seul.

--- COMMIT VALIDÉ — FICHIER UNIQUE : git checkout ---

Extrait un seul fichier depuis un commit spécifique et le place directement dans la zone de staging.

Restaurer depuis l'avant-dernier commit :
  git checkout HEAD~1 -- report.md
  Le -- sépare la référence du nom de fichier.

Vérifier puis valider :
  git status           (Confirme que le fichier est bien en staging.)
  git commit -m "..."  (Enregistre la restauration dans un nouveau commit.)

--- FICHIER EN STAGING — NON COMMITÉ : git restore --staged ---

Retire un fichier de la zone de staging et le renvoie dans le répertoire de travail. Les modifications ne sont pas perdues.

Déstocker un seul fichier :
  git restore --staged report.md

Déstocker tous les fichiers :
  git restore --staged
  Sans nom de fichier, retire tous les fichiers de la zone de staging.

Le fichier reste modifié dans le répertoire de travail — corrigez-le, puis restager avec git add.

--- OPTIONS DE GIT REVERT ---

--no-edit
  N'ouvre pas l'éditeur de texte — conserve le message de commit généré automatiquement.

-n  (--no-commit)
  Annule sans créer de commit immédiatement — laisse le temps de réviser les fichiers avant de valider.

--- TABLEAU RÉCAPITULATIF ---

  git revert HEAD                    → Revenir à la version d'un commit donné pour tous les fichiers
  git revert HEAD --no-edit          → Revenir à une version précédente sans ouvrir d'éditeur de texte
  git revert HEAD -n                 → Annuler les modifications sans créer de nouveau commit
  git checkout HEAD~1 -- report.md   → Restaurer un fichier spécifique dans l'état du commit précédent
  git restore --staged report.md     → Supprimer un fichier spécifique de la zone de staging
  git restore --staged               → Supprimer tous les fichiers de la zone de staging

INFOGRAPHIE 08 — Récapitulatif — Git & GitHub
================================================================

Vous maîtrisez maintenant les outils fondamentaux pour versionner, analyser et restaurer vos projets de données.

--- CHAPITRE 1 : Fondamentaux de Git ---

Gestion de versions
Avantages, usages et concept de snapshot — suivi des modifications, rollback, collaboration.

Navigation dans le terminal
  pwd   ls   cd

Créer et initialiser un dépôt
  git init   git status

Suivre et valider des fichiers
  git add   git commit
  Zone de staging (sélection) → commit (snapshot permanent).

--- CHAPITRE 2 : Historique, Comparaison & Restauration ---

Les 3 composants internes de Git
  Commit (métadonnées) · Arborescence (liste des fichiers) · Blob (contenu compressé)

Consulter et inspecter l'historique
  git log   git show [hash]
  Filtrer par nombre, fichier, date · identifier les hashs de commit.

Comparer les états
  git diff   git diff --staged   git diff HEAD~1 HEAD
  Entre le répertoire de travail, le staging et l'historique des commits.

Restaurer des fichiers
  git revert HEAD   git checkout HEAD~1 -- f   git restore --staged
  Annuler un commit, restaurer un fichier unique, déstocker.

--- RÉFÉRENCE DES COMMANDES ---

Terminal    : pwd  ls  cd

Initialiser : git init  git status

Versionner  : git add [fichier]  git add .  git commit -m "..."

Historique  : git log  git log -n  git log --since  git log [fichier]  git show [hash]

Comparer    : git diff [fichier]  git diff --staged  git diff HEAD~1 HEAD  git diff [h1] [h2]

Restaurer   : git revert HEAD  git revert HEAD --no-edit  git checkout HEAD~1 -- f  git restore --staged
